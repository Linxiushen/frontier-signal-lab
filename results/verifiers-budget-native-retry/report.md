## Caller, intervention and frozen limits

The actual caller is a finite evaluation worker that shares a development/final spend across restarts. At larger worker counts, physical SDK retries can multiply provider cost while logical episode counts remain constant. This study does not measure that scaling. It integrates an opt-in [physical SQLite budget](../../experiments/eval_http_budget.py) into the [actual provider boundary](../../experiments/verifiers_budget_retry_suite.py), using the unchanged [v2 native worker](../../experiments/verifiers_budget_suite_v2.py) and [Verifiers f5f5c9a](https://github.com/PrimeIntellect-ai/verifiers/tree/f5f5c9ace86b9720049cb6e98d05d14d77042486). The original runner and v2 caller remain independently callable as rollback options.

The logical ledger reserves before native entry and commits the genuine score receipt before completion. The separate physical ledger commits a global ordinal, per-attempt ordinal and body hash before any provider response. A prepared response status is persisted before write; write completion is recorded afterward. Failed, duplicate, conflicting and denied requests reaching admission consume ordinals without refunds. The global limit is six; the per-attempt limit is two. Inbound traffic, denied-request log growth and failures during pre-admission Content-Length parsing/body reads are outside that cap. This is a trusted fixture endpoint, with no tenant authentication or general service resource guarantee.

The [preregistered specification](../../research/protocols/verifiers-budget-native-retry-v1.json), [builder](../../experiments/prepare_verifiers_budget_retry.py) and [exact generated input](../../fixtures/verifiers-budget-native-retry/protocol.json) bind the code, source, data and locks.
