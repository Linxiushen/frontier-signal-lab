The change supplies an actual integration point for H4: the Anthropic Messages transport called by Pi's agent runtime. A session can send a server reply ID plus the new suffix after an earlier successful response. ## What the landed caller does

The [transport](https://github.com/earendil-works/pi/blob/a758f3ae4cdb193a6949c81318fe1b3caa4814a1/packages/ai/src/api/anthropic-messages.ts) builds the full request and awaits `onPayload` before preparing continuation. Its process-local map stores a reply ID, prefix length and fingerprint for each session. The map caps entries at10,000 and evicts the least recently updated entry. It is not a persistent transcript or restart recovery store.

Continuation requires messages beyond the saved prefix and a matching fingerprint of selected fixed fields and the converted prefix. Fixed fields include provider, base URL, model, system, tools, thinking, output configuration, tool choice, betas and fallbacks. Message comparison normalizes string content into text blocks and omits `cache_control` keys. The [short hash](https://github.com/earendil-works/pi/blob/a758f3ae4cdb193a6949c81318fe1b3caa4814a1/packages/ai/src/utils/hash.ts) is a deterministic pair of32-bit accumulators; this is neither cryptographic identity nor collision-free exact equality over every request field. The implementation deletes the old entry before sending a continuation. A cleanly completed stream with a response ID and the expected model can establish the next entry, including a reply ending at the output length limit. Incomplete, errored, aborted, refused or fallback-model replies do not.

The default capability check requires provider `anthropic` and a base URL containing `api.anthropic.com`, with a compatibility override. That substring test is not an authenticated endpoint or account identity check. Session ID and request fingerprinting do not establish current user authority or distinguish every credential/configuration change.

Four named thread errors trigger one full-request resend as a new thread. A specifically unsupported thread request, or a code-less400 whose message contains lowercase `thread`, triggers a normal full-request fallback. When that send obtains an accepted HTTP response, the session is marked off before its stream is consumed; a later stream error or abort can leave it off. Generic errors propagate. This is narrower than the PR description's statement that other errors turn threads off. Resending happens around request creation, not after a provider stream has already started. The SDK retries are disabled; the existing [provider retry helper](https://github.com/earendil-works/pi/blob/a758f3ae4cdb193a6949c81318fe1b3caa4814a1/packages/ai/src/utils/provider-retry.ts) can independently retry each send when configured. Therefore one application fallback does not imply a single physical request or a global turn-wide retry budget. An eligible session marked off, or a warmer using `disableContinuation`, can still carry the automatic threads beta. An explicit `anthropic-beta` header replaces the automatic beta list; a null value removes it.

The [cache warmer](https://github.com/earendil-works/pi/blob/a758f3ae4cdb193a6949c81318fe1b3caa4814a1/packages/coding-agent/src/core/cache-warmer.ts) uses the real model runtime with `disableContinuation: true`, `maxTokens: 1`, `maxRetries: 0` and its own abort signal. Its replay does not consume or replace the conversation's continuation entry. Session resource cleanup deletes map entries synchronously. `AgentSession.dispose()` signals cancellation and cleans resources without awaiting idle; the separate asynchronous abort path does await idle. The ordinary Agent also rejects overlapping active runs. These observations motivate a lifecycle test; they do not establish a race in the normal single-Agent path or prove settlement after disposal.

## Evidence and remaining gate

All14 landed changed paths were compared against the immutable parent, alongside selected direct helpers and real caller paths. The new [thread tests](https://github.com/earendil-works/pi/blob/a758f3ae4cdb193a6949c81318fe1b3caa4814a1/packages/ai/test/anthropic-message-threads.test.ts) exercise fake fetch/SSE responses: suffix continuation, selected configuration changes, thread rejection fallback, retry interaction, failed/aborted streams, OAuth tool names and cache warming. Reading these tests establishes their design, not a passing run or actual Anthropic behavior. No complete runtime dependency or authorization audit is claimed.

For a future separately registered native caller comparison, pin the adjacent packaged runtime, task, model, provider/account identity, settings, score/evaluator bytes and total request/token/time/resource ceilings before running. Retain immutable stored messages and actual wire attempts, including full-request rollback, retry cause, stream acceptance, cancellation and cleanup. Exercise unchanged prefixes, semantically changed tool arguments/results, selected configuration changes and disabled continuation. Include a cache-warming overlap and the real session lifecycle; only then assess whether effects, sampled tokens, masks and rewards remain attributable to the same versioned attempt. Existing two-restart/current-authority gates remain unmet.

Any performance arm must report task success/quality, effective throughput, end-to-end and tail latency, peak resources/communication and observation overhead for a fixed workload. Compare the normal full-request path with continuation under the same budget and preserve fallback/failed attempts. No performance or scientific status is upgraded by this source review. H1's frozen negative results and H2–H4's existing acceptance conditions remain unchanged.
