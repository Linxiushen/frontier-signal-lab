# Compact-state replay revision: source progress, native results still unreplicated

The author of [FLA PR #1681](https://github.com/fla-org/flash-linear-attention/pull/1681) posted a [revision report](https://github.com/fla-org/flash-linear-attention/pull/1681#issuecomment-6706003166) at 11:06:39 UTC on 7 November 2026. Its new head, [`881d2cc5bb6a0f791bf83b3a9de4aeb941efe08d`](https://github.com/fla-org/flash-linear-attention/commit/881d2cc5bb6a0f791bf83b3a9de4aeb941efe08d), is a direct child of the head in our [earlier contract review](2026-11-07-compact-state-native-contracts.md). The source now changes the selector and verifier paths identified there. The PR remains open in our capture; this establishes a branch revision, without establishing maintainer acceptance or a released fix. We authenticated complete pinned files and read the source without importing or executing upstream code.

In [KDA backward](https://github.com/fla-org/flash-linear-attention/blob/881d2cc5bb6a0f791bf83b3a9de4aeb941efe08d/fla/ops/kda/chunk_bwd.py), singleton contiguous-CP selection now computes `torch.searchsorted(cu_seqlens, cu_seqlens[-1]) - 1` on device. Both relevant backward kernels load the resulting tensor with `tl.load`; the common wrapper removes the earlier host-side range check. For sorted packed offsets with at least one nonempty sequence and repeated final offsets, the leftmost final offset identifies the end of the last nonempty sequence. The source therefore carries live metadata into the captured calculation instead of selecting `len(cu_seqlens) - 2` from the static buffer length. We have not established GPU replay correctness or measured any gradient error.

The [TileLang verifier](https://github.com/fla-org/flash-linear-attention/blob/881d2cc5bb6a0f791bf83b3a9de4aeb941efe08d/fla/ops/kda/backends/tilelang/__init__.py) now explicitly accepts the compact argument names and declines compact layouts with a reason. This changes the earlier signature-exception rejection into an explicit capability boundary. Compact execution still falls back; the patch does not add TileLang compact support or demonstrate a speed improvement. The separate [Triton-Ascend CP adapter](https://github.com/fla-org/flash-linear-attention/blob/881d2cc5bb6a0f791bf83b3a9de4aeb941efe08d/fla/ops/cp/backends/triton_ascend/__init__.py) now rejects singleton state after checking that the input device is NPU. That source identifies an Ascend NPU guard. The author's phrase “intra-card CP” does not independently identify the NVIDIA adapter alleged in the earlier review, so that earlier attribution limit remains.

Three added [test definitions](https://github.com/fla-org/flash-linear-attention/blob/881d2cc5bb6a0f791bf83b3a9de4aeb941efe08d/tests/ops/test_kda_compact_state.py) check plain-versus-compact verifier behavior, singleton rejection using an NPU-shaped namespace, and tensor equality through the public fused entry with TileLang availability/enabled patched. The last comparison does not record selected-backend identity, and the namespace check does not run an NPU kernel. The existing [CP KDA graph test](https://github.com/fla-org/flash-linear-attention/blob/881d2cc5bb6a0f791bf83b3a9de4aeb941efe08d/tests/cp/test_graph.py), including replay with padded sequence metadata, has unchanged bytes from the reviewed parent. It calls `chunk_kda` without an explicit `compact_h` argument; activation/default threading through the public wrapper is outside this bounded capture, so we have not independently established compact-layout coverage. These are inspected test definitions, not tests run by this project.

The author reports H200 results: 17 compact-state passes, 11 + 6 CP passes, two graph passes, and 227 full-KDA passes with 15 skips and five lower-bound `dA` failures. The same five failures and two graph passes are reported on the PR base. We have not reproduced these outcomes or authenticated raw native logs. They cannot establish our own GPU validation, measured memory saving, training quality or useful throughput.

The actual integration remains packed KDA training under contiguous CP and graph replay. The engineering lesson is narrower than a new algorithm claim: state compaction must preserve live sequence identity and make backend exclusions explicit. This revision advances those source contracts. It does not supply evidence for our H1 residual bank or change its saved negative training result.

A justified future integration would reuse these native callers and tests. A separate protocol would fix the patch/fallback, intended route, hardware/software, dtype, seeds, shapes, packed lengths, ranks and resource ceilings before execution. It would require forward/full-gradient tolerances across changing replay layouts and rollback, then matched held-out quality, useful throughput, end-to-end/tail latency, peak resources, communication and observation cost, accounting for compilation and capture separately. This is a proposed acceptance boundary, not a new preregistration or observer prerequisite. All H1 negatives and existing H2–H4 statuses and closed finite gates remain unchanged.
