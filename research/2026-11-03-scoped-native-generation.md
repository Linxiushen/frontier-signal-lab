# Scoped identities through the native generation and recovery chain

Two independently allocated native Sessions can reuse the same numeric conversation IDs and request keys. A key-only remote effect store then couples work that should remain independent. The scoped-v2 adapter already binds routing and SQL identity to `(scope,key)`; this result connects that opt-in adapter to the actual installed Harness/GenerationTask/ToolTask and its restart path.

The separately preregistered finite H2 suite passed its frozen auditor, and a reviewer independently reread the saved native/HTTP evidence and nine immutable SQLite copies. Eighteen arrivals produced 12 admissions and 6 overload refusals; 4 exact host retries reused submissions and 4 changed-content requests conflicted. Twelve generation/tool pairs reached 24 native terminal tasks across two forced native kills/reopens. Two positive tool checkpoints reentered execution on their original task IDs, so 14 execute entries represent 12 unique tool tasks. Five reservations were recovered, and active reservations ended at 0.

Both Sessions intentionally reuse every key with different payloads. Nine expected eligible scoped effects coexist at count 1. Asymmetric remote revocation, host revocation and pre-effect cancellation leave three identities without effects while their other-scope counterparts succeed. A separate post-commit cancelled/revoked identity recovers its historical receipt by GET while remote permission is still false, before the next authority version is installed. This acknowledges an existing effect without issuing another mutation for recovery. The exact saved SQL records 13 effect GETs and 14 POSTs: 9 created, 1 denied, 2 duplicate and 2 conflict POST outcomes.

Suite time was 7.563 s, excluding 31.062 s of source/runtime authentication. Full controller time was 38.625 s and complete CLI time 39.062 s. Offer-to-observed-terminal p50/p95/max were 151/2434/2434 ms, including the imposed holds/restarts. Nine fixture effects divided by suite time gives 1.190 effects/s descriptively. There is no baseline, causal speedup, SLO or real-model-quality conclusion. Native/server sampled private maxima were 109,461,504/15,421,440 bytes; sampling gaps and distinct OS peak counters remain in the report. Encoded HTTP request bodies and observed response chunks total 3273/14697 bytes only for settled result events, not wire traffic. The held killed request is visible in persisted SQL but need not have a client result event.

The original concurrent H2 freeze remains failed with `KeyError('service')`; its report and 95-file raw archive were verified unchanged. The new result uses a separate scoped workload, protocol and reviewed eight-source freeze. No old failed acceptance is promoted, and no scientific retry occurred. H1/H3/H4 conclusions remain unchanged.

This is actual single-host native integration with official deterministic local Faux and real loopback HTTP/SQLite under one trusted owner. It establishes only this finite namespace/admission/permission/recovery trace. It does not establish tenant authentication, concurrent owners, arbitrary races, atomic host/remote policy, general external exactly-once, real model quality, GPU/distributed operation or production performance. Capacity 2 bounds active reservations per Session while histories still grow. The opt-in wrapper/new effect database can be omitted without migrating or overwriting the original service/database.
