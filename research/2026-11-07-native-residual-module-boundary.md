# Merged residual modules: a reusable interface, with model adoption still separate

The authenticated squash commit is [`de66a30ca8f7224ba3261b92f1a02ab0cb0fa98f`](https://github.com/fla-org/flash-linear-attention/commit/de66a30ca8f7224ba3261b92f1a02ab0cb0fa98f), directly after `38db7118235871e782ebf0a81dbaa431cffda36f`. This is a new merge transition, following the earlier unmerged proposal; the module design is not a new announcement today. Our capture authenticates eight changed paths, the unchanged GLA caller, and pinned license/policy material. We read source and test definitions without importing or executing upstream code. No tagged release was established.

The new [BaseResidual](https://github.com/fla-org/flash-linear-attention/blob/de66a30ca8f7224ba3261b92f1a02ab0cb0fa98f/fla/modules/residuals/base.py) separates aggregation from a model's branch computation. `initialize` creates state; `pre` returns a normalized branch input and update context; the model executes its branch; `post` returns the next state. `readout` returns the aggregate without final branch/output normalization, while calling the output module additionally normalizes it. Attention key normalization still occurs inside attention aggregation. State/context retain autograd connections; the interface requires callers to avoid mutation or caching on the module. It supplies an integration boundary, not a complete training loop.

[StandardResidual](https://github.com/fla-org/flash-linear-attention/blob/de66a30ca8f7224ba3261b92f1a02ab0cb0fa98f/fla/modules/residuals/standard.py) can retain two summands until the next normalization instead of immediately materializing their sum. Its fused add/normalization route preserves the residual dtype and produces the normalized branch dtype; unfused addition follows PyTorch promotion. These are different rounding contracts. A matched comparison must fix fusion and dtype rather than treating every Standard configuration as an interchangeable numerical baseline.

[AttentionResidual](https://github.com/fla-org/flash-linear-attention/blob/de66a30ca8f7224ba3261b92f1a02ab0cb0fa98f/fla/modules/residuals/attnres.py) retains the embedding plus preceding branch outputs or block sums. `block_size` counts attention/MLP branch outputs, so a transformer layer can contribute two; size 1 is Full AttnRes. `post` builds a new list, begins a block at its boundary, or adds to its current partial sum. On the first update it casts the embedding to the branch-output dtype. The first `pre` directly normalizes the embedding; later reads use the existing fused AttnRes operator and each module's query. Queries initialize to zero. The class declares `supports_reentrant_checkpointing = False`; that declaration alone does not establish checkpoint correctness in a consuming model. Fewer logical block entries do not establish peak memory savings or model-quality preservation.

Model adoption remains separate. The merge changes module exports and adds the residual implementations/tests; it changes no existing model or kernel file. The pinned [GLA implementation](https://github.com/fla-org/flash-linear-attention/blob/de66a30ca8f7224ba3261b92f1a02ab0cb0fa98f/fla/models/gla/modeling_gla.py) already has optional inline AttnRes with direct `fused_attnres` calls. It does not use these new residual classes. The author's separate [#1422 integration](https://github.com/fla-org/flash-linear-attention/pull/1422) therefore must not be conflated with either first introducing AttnRes to GLA or this interface already being wired into an existing model. We did not review that separate PR's implementation in this capture.

The two added numerical test definitions cover six connected SiLU branches: eight Standard configurations and five Full/Block AttnRes configurations. They compare branch inputs, stored state, final output/dtype and input/parameter gradients against differentiable references at tolerance 0.005. The gradient comparisons allow unused parameters and check matching `None`; they do not require every query to receive a nonzero gradient. Both tests explicitly skip CPU. These definitions cover useful aggregation contracts, without exercising a full attention/MLP model, a checkpointed training step or held-out quality. No local test was run.

The PR body reports all 13 configurations passing on GB200 at earlier revision `ddc122a8` and says the test functions are unchanged. It also reports residual cases passing in an A2 NPU run at `246eec37`, whose full suite failed in a separate GroupLinear float64 case. Those are author reports, not this project's reproduced results or a current merged-head CI audit. H100 smoke remains unverified. The reported GB200 benchmark compares earlier revisions using six BF16 SiLU branches, seed 42, three alternating rounds and timings including SiLU/gradient clearing. It retains small regressions, including 1.9% for one AttnRes forward/backward workload; NCU was not run. These small module measurements establish no model-throughput, peak-resource or training-quality benefit here.

For our H1 work, this merge advances the availability of a reusable upstream residual interface. It supplies no evidence that our compression policy improves quality or cost, and does not rescue the saved negative training screens. A justified future caller would explicitly select Standard versus Full/Block AttnRes, branch order, dtype/fusion, checkpoint mode and the existing implementation as rollback. Before execution it would separately preregister matched model/data/optimizer/token and time budgets, complete forward/backward/update and restart semantics where applicable, held-out quality, useful throughput, end-to-end/tail latency, measured peak resources/communication and observation cost. No new experiment, dependency adoption, observer prerequisite or scientific gate is admitted by this source review; all H1 negatives and existing H2–H4 statuses and closed finite gates remain intact.
