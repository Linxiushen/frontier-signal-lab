# 第一轮研究判断 · 2026-10-15

观察基准：北京时间 2026-10-15 晚间。这里的“下一步”是我们的可检验研究假设，不代表研究者或机构的内部路线。优先级是本项目的执行排序，不是对未来事件的概率估计。

## P0：深度路由 × 优化器 × 硬件预算

**公开事实。** Nathan Chen 的 10 月 15 日原帖宣布离开 Kimi，并明确提到 KDA kernels、Attention Residuals 和优化器；没有写加入 Anthropic。个人站将兴趣列为模型架构、优化器和 hardware-aligned algorithms/kernels。官方 AttnRes 仓库说明 full depth attention 的存储问题与 block 近似。FLA 合并 PR #688 是比个人旧 fork 更强的 KDA 实际贡献证据。

**研究判断。** 可以优先研究：非均匀深度分组、残差 bank 量化、动态路由与训练稳定性的相互影响；按相同训练预算核算真实收益。这个判断连接三条公开工作线，但并不能确定作者下一篇论文会做什么。

**公开讨论。** AttnRes #9 问非均匀 block size，#2 提出不同的 routing formulation。它们均为第三方讨论。#11 中自称某机构与“省显存 65%”的提案没有经过本项目验证，不用作机构或性能事实。

**本轮新代码信号。** 在线快照抓到 FLA [commit 3995fd7](https://github.com/fla-org/flash-linear-attention/commit/3995fd79a49210e1f1cb0b90b3bf3df9fef63707)，标题为“Make KDA safe_gate diagonal path independent of future gates”，作者 `xy200303`。这是上游因果约束与 kernel 设计的直接交叉线索，不是 Nathan 的新贡献，也不能仅凭提交说明宣称本项目验证了修复。后续 kernel 实验应包含未来 token 扰动不影响过去输出、partial chunk 与 stride 边界等不变性检查。

**现在执行。** 运行 `experiments/attnres_budget_probe.py`，先比较固定/非均匀 block-sum 代理、历史子集、int8 bank 与 oracle top-k 的数值损失和逻辑预算。输出中保留负结果与长尾误差。

**下一实验门槛。** 小模型训练比较等 token 与等 wall-clock 两种预算；固定数据/初始化，报告验证损失、多 seed、梯度范数、路由熵、GPU 峰值显存与 tokens/s。先确认上游代码授权再集成；当前独立实现。

**失效条件。** 如果数值损失在稀有信息上过大，或真实反向/通信代价抵消存储收益，就暂停该压缩路线。operator 误差低也不能代替语言模型训练结果。

## P1：自动研究循环中的封闭终评与预算审计

**公开事实。** SakanaAI / AI-Scientist-v3 仓库创建于 2026-10-11，本轮观察到 10 月 15 日有代码推送。其公开 README 描述 sealed final evaluation、消融、不可变 task snapshot 等机制。Robert Tjarko Lange 的个人 GitHub 自述 Meta-Discovery @SakanaAI。

**研究判断。** 下一批有价值的独立研究，可能是怎样防止自动实验循环反复适应公开验证集，以及如何审计 agent 的实验预算与最终结论。仓库新出现是强信号，不代表其所有行为已被我们复现。

**最小实验。** 固定候选生成预算，以公开验证反馈进行自适应选择，最终只访问一次独立 holdout。报告选择偏差、重复试验次数、预算与真实泛化差距；之后接入真实 coding agent。

**后续观察。** 官方围绕 evaluation、task snapshot、optimizer memory 的代码变化、维护者回复和可重复失败案例。若 holdout 已受 prompt 或日志泄漏污染，则本次终评无效。

## P1：可验证 RL 环境的奖励与评测一致性

**公开事实。** Will Brown 的个人站介绍其 Prime Intellect Applied Research 工作；`PrimeIntellect-ai/verifiers` 是可检查的公开环境/训练工具线索。机构自述不等于已核验入职日期。

**研究判断。** 奖励函数、环境版本和终评协议能否一致，比单纯扩大训练回合更适合独立小团队切入。

**最小实验。** 对同一任务变换格式、工具错误、环境版本和重复执行，检测 reward hacking、非幂等评分与训练/终评不一致。以失败案例覆盖率为目标，不承诺提升模型能力。

## P1：长任务 agent 的上下文与事件一致性

**公开讨论。** pi 的 #10979 报告 extension hook 挂起导致最终消息未持久化；#10982 报告 compact 与新 turn 并发读取旧上下文。这两条被新贡献者自动关单策略关闭，不能把 closed 理解为修复或反证；#10979 的一条公开回复认为应由 extension 修复。OpenClaw PR #173018 讨论重启后不可投递的子任务完成事件被重新激活。这里记录的是报告和待审代码，不是本项目已经复现的漏洞。

**研究判断。** 研究机会在上下文版本、写前日志、completion delivery 和故障恢复的可验证合同。它适合 CPU 故障注入，也与本账号既有 harness/trace 工作相接。

**已执行的最小实验。** `experiments/recovery_contract_probe.py` 在消息流程各边界枚举 crash，并覆盖 hook 挂起、compaction 并发、重复 child completion、终止重试与评分失败证据。33 条轨迹比较 naive、durable log、versioned journal 三个协议。只保证原子持久写和单进程 fail-stop 的有限模型；外部副作用需要自己的事务/幂等键。结果见 `results/recovery-contract/report.md`。
