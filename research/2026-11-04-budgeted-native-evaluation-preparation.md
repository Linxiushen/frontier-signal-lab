# A resumable evaluation budget caller, awaiting native execution

The new opt-in [ledger](../experiments/eval_budget_runner.py) reserves an episode and its scoring allowance before entering a native evaluation. Completed results survive reopening; an uncertain reservation burns its allowance rather than buying a replacement attempt. SQLite binds the protocol identity and fixed budget, and selection commits the highest completed development reward before a single final allowance becomes available. The wrapper can be removed by calling the original runner directly. These rules apply to a trusted caller using this interface; they do not constrain arbitrary code that bypasses it.

The [complete integration driver](../experiments/verifiers_budget_suite.py) calls the actual Verifiers `run_episodes → Env.run_slot → NullHarness → EvalClient → EchoTask.echoed` chain at pinned source [`f5f5c9a`](https://github.com/PrimeIntellect-ai/verifiers/commit/f5f5c9ace86b9720049cb6e98d05d14d77042486). It leaves upstream code unchanged. Its provider is a deterministic loopback HTTP fixture. Two development entries, a third allowance burned before entry, two forced process deaths/reopens, evaluator-version refusal and one final entry are specified in [the implementation protocol](protocols/verifiers-budget-v1.json). The [protocol builder](../experiments/prepare_verifiers_budget.py) requires both completed dependency locks before writing a freeze. **No execution freeze or native evaluation has been produced.**

An initial test exposed an SQLite connection left open when constructor identity validation failed; the constructor now closes it on every initialization error. These tests do not validate the native integration driver.
