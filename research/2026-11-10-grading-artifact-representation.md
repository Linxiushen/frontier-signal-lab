# Grading must consume the artifact representation that was validated

Verifiers [PR 3115](https://github.com/PrimeIntellect-ai/verifiers/pull/3115), by `rasdani`, merged at 2026-11-10 03:43:39 UTC as [4fa6c4e3](https://github.com/PrimeIntellect-ai/verifiers/commit/4fa6c4e3886710a23036beb98243f9e9bf0ae8d6). The landed code changes an actual isolated grading path: archives validated with Python are rebuilt before the grading runtime receives them, and isolated Harbor graders start with an empty verifier log directory. This is a source and test-design review. No upstream test, native runner, model or scientific experiment ran here.

The author reports an RL trial in which an agent-controlled archive passed Python's member checks but the grading box's GNU tar interpreted additional content. A substituted grader tool then wrote reward 1.0 without running the tests. The linked trial is private; its archive, trace, complete denominator and execution are unavailable here. The event and reward are an **author report**, not our reproduction. The author also explicitly says end-to-end Docker/Prime validation had not run. Bot summaries in the PR are not independent evidence.

## The concrete caller and change

At the pinned revision, [Rollout finalization](https://github.com/PrimeIntellect-ai/verifiers/blob/4fa6c4e3886710a23036beb98243f9e9bf0ae8d6/verifiers/v1/rollout.py) collects submission artifacts before isolated grading. [grade_task](https://github.com/PrimeIntellect-ai/verifiers/blob/4fa6c4e3886710a23036beb98243f9e9bf0ae8d6/verifiers/v1/grading.py) opens a fresh verifier, runs task setup, calls `restore`, invokes the task's verifier staging and then scores a copied trace. Retry setup/backoff/scoring share a remaining deadline; this source does not establish durable restart or total resource accounting.

The [adjacent parent](https://github.com/PrimeIntellect-ai/verifiers/blob/065860f569cf3b7f8c66f204616f7f3065dd5266/verifiers/v1/utils/artifacts.py) validates the Python member view, then writes the original archive bytes to the runtime for `tar -xf ... -C /`. The [landed implementation](https://github.com/PrimeIntellect-ai/verifiers/blob/4fa6c4e3886710a23036beb98243f9e9bf0ae8d6/verifiers/v1/utils/artifacts.py) validates all roots and rebuilds every non-null archive **before clearing any runtime root**. It emits fresh PAX headers from the members Python reads, supporting regular files, directories, symlinks and hard links. It preserves owner IDs/names, mtimes and ordinary permission bits, while masking modes with `0o777`. Sparse members are refused before rebuilding. Existing path, duplicate, symlink-chain and hard-link confinement checks remain in the validation path; subprocess restore remains explicitly refused.

The [Harbor caller](https://github.com/PrimeIntellect-ai/verifiers/blob/4fa6c4e3886710a23036beb98243f9e9bf0ae8d6/verifiers/v1/tasksets/harbor/taskset.py) now removes the whole `/logs/verifier` directory when `wipe` is true or scoring mode is isolated, before recreating it. Shared grading without wipe retains its prior directory behavior and still removes the two reward files. `run_verifier` executes `bash /tests/test.sh`, records bounded output excerpts and reads the configured reward; a reward file remains authoritative even if the script exits nonzero. The patch changes which restored state can precede that invocation, not the reward-file policy.

Validation/rebuilding before root clearing avoids destructive runtime changes for an archive rejected in those stages. It is not a transaction over later writes/extractions: the source clears roots before restoring individual archives, and a later runtime failure can still leave a partial workspace. Nor does fresh grading alone make a root-controlled shared agent/grader box trustworthy. The author explicitly excludes same-box grading from the repair's threat boundary; the reported roughly 39k/41k private-task population is not independently verified.

## What the public tests establish as designs

All three changed files were acquired in full at the merge revision, with both modified parent files and complete parent/landed trees. The additional full rollout, grading and Harbor network-test sources fix the caller context; the current MIT license blob is authenticated. This is selected source closure, not a dependency or security audit.

The new [artifact tests](https://github.com/PrimeIntellect-ai/verifiers/blob/4fa6c4e3886710a23036beb98243f9e9bf0ae8d6/tests/unit/utils/test_artifacts.py) define three checks: ownership/ordinary-mode retention with special bits removed; equality of Python-visible member names and system-tar listings for files, long names and links; and refusal of a sparse header declaring a huge logical file. The runtime double records writes and accepts every command. The system-tar check lists rebuilt bytes and skips if tar is absent; it does not execute a container grader, compare every extracted content/metadata property or pin every tar implementation. The additional Harbor network tests concern parsed shared-mode policy, not this log-directory deletion or an end-to-end attack replay. Author unit-test pass statements remain external reports; no CI result was acquired for this source review.

## Engineering implication and next acceptance boundary

Our inference is that an artifact digest plus a validated member list is insufficient if a downstream parser consumes a different representation. A real evaluation receipt should bind the original submission, normalized archive, grader image/tool versions, task/data/scoring version, attempt and resulting reward. Old grader-produced files also need an explicit provenance policy. This sharpens H3/H4's existing version/retry/denominator requirement; it does not upgrade their scientific status or reopen a closed fixture.

At larger artifact volumes, rebuilding adds host parsing, allocation and transfer preparation. The code retains original archives while constructing a dictionary of rebuilt bytes before root clearing. Sparse rejection prevents one expansion mechanism; an input archive byte budget is not a measured peak-memory or rebuilt-output ceiling. No throughput, tail latency, peak resource, communication or observer-overhead benefit is measured here.

A future justified integration belongs in this actual isolated `grade_task`/Harbor chain, with the prior pinned runner retained for rollback. Before execution it must separately freeze harmless file/link/PAX and malformed/sparse controls, original/normalized/scoring identities, attempted/admitted/scored/failed members, total retry/token/time and archive/member/host-memory limits, cancellation boundaries and two process restarts. It should require that rejected submissions yield no accepted reward, staging cannot reuse old verifier outputs, exact replay cannot grant a new spend, and successful grading consumes the recorded normalized bytes. Applicable success/quality, effective throughput, end-to-end and tail latency, peak resources/communication and observation cost must accompany any performance comparison. No new protocol is frozen here, and the closed Echo/HTTP budget fixtures are not substitutes for these artifact checks.
