# Native evaluation budget integration: failed frozen attempt

One preregistered scientific attempt failed on 2026-11-05. It reached the actual pinned Verifiers runner, NullHarness subprocess, EvalClient HTTP path and EchoTask scorer. Two native entries produced one completed episode with one `echoed` reward of 0.0; the other episode failed. Five provider HTTP arrivals comprised one accepted and four failed arrivals. Worker PID 8 was verified killed with SIGKILL and exit -9; its successor PID 72 exited 1. The third worker, second forced-death boundary, reservation burn, selection and final evaluation were not reached. The freeze was not rerun or repaired after observing the failure.

Project, pinned source, environment and frozen inputs were read-only; external networking and image pulls were disabled. Client connect/read/write/pool timeouts were 2/3/3/2 s. ## Observed failure and mechanism

The first `dev-bad` model call ended with `ProviderError` 504 after 3.0247 s, close to the frozen 3 s read timeout. Pinned EvalClient maps an HTTPX timeout to 504, but the exact timeout subtype was not retained. The fixture prepared a 319-byte response and then encountered `BrokenPipeError` writing it. Prepared bytes are not proof that they were delivered. A second identical 261-byte request consumed the same generated response successfully, and the native scorer committed the deliberately mismatching answer's reward 0.0. This is a fixture correctness value, not model quality.

The earlier failed arrival consumed a global ordinal. Our frozen fixture routes `fixture-good` to `dev-good` only when the received ordinal is two; otherwise it selects `final-once`. Consequently, after `dev-bad` used arrivals one and two, a normal phase-two good request at arrival three would select an unreserved final attempt. That is a deterministic retry-fragile identity defect in our fixture. The three good-episode calls returned HTTP 500 and the arrival receipts record assertion failures. The specific SQL assertion for arrival three is a source-derived diagnosis: its raw body and assertion location were not retained. Arrivals four and five also exceed the frozen three-arrival guard. No upstream defect or general recovery failure is established by this fixture bug.

The traces contain two HTTP calls in `dev-bad` and three in `dev-good`, although native episode/agent retries were zero. The bundled harness uses the OpenAI SDK; zero episode retries do not imply one received HTTP request per episode. The exact SDK default and retry scheduling were not measured separately.

Cold initialization is a plausible explanation for the first delay, not a measured cause. The fixture imports the genuine dialect on its first request before replying; the retry uses already imported code. No import timing or original receive/prepared timestamp was retained, and scheduling, resource or transport delay remains possible.
