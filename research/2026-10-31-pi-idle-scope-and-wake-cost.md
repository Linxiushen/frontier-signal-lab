## What the pinned source changes

The actual caller is Pi durable's `HarnessImpl`/`TaskScheduler` following Session commit publications. Previously a changed task publication called `#settleIdle()` across all kept conversation contexts, and finding expiry scanned their retained ranges again. The new observer collects conversations above tasks that become live or end **before** `#sweep()` can discard ownership chains, then calls `#settleIdle(dirty)` for those scopes. Unknown chains fall back to a full check; chain loads mark `#unknownsChanged` and request reconcile so an unrelated idle waiter is not stranded merely because no task changed in that scope.

Idle contexts enter `#idleOrder` by `idleSince`. Expiry walks oldest first and stops at the first nonexpired range. A backward clock observation re-sorts the index; zero retention drops every idle range, even when its recorded idle start lies after the current clock. Entry-only commits remove expired/unextendable ranges from both maps. Reconcile still checks expiry for hosts declining background timers. Close clears the idle index.

`wake()` scans the sleeping-task set for its next future deadline. It avoids its full live-task eligibility scan while an invocation/reconciliation is already active. **It still scans sleeping tasks**, and when idle it can still scan live tasks; unknown chains can still trigger whole-scope checks. This is not a constant-cost guarantee for every task graph.

The new internal symbol exposes `contexts`, `idleContexts`, `idleMismatches` and `fullIdleChecks` solely as a diagnostic. Calling it recomputes idle truth on demand; it is not free continuous monitoring and should be kept outside timing measurements.

## Engineering implication and next gate

This is materially new source evidence for the H2 implementation choice: retained-context bookkeeping and wake eligibility can become an avoidable per-commit CPU cost. It justifies considering scope invalidation and an expiry index **inside a single durable runtime selected and pinned before future preregistration**; it does not clear H2's existing admission, current authority, cancellation, once-only effects or two-real-process-restart gates. No native H2 runtime is claimed integrated by this source review.

Before any future preregistration, select and pin a single H2 runtime. Before any run, separately pin the authentic parent/candidate packages, actual native caller/import closure, supported persistence/multi-session topology, arrival process, fixed conversation/retention/sleep/owner-chain workloads and resource/time ceilings. Predeclare correctness acceptance as zero discrepancy against a full recompute for idle waiters/context identities and wake deadlines, including unknown-chain/reopen, backwards-clock, zero-retention and declined-timer controls. Retain the costly full recompute as a separate reference arm, not timed observer work. Test cancellation and real authority/effect receipts with held admissions and two process restarts in that single H2 harness; no restart or admission success follows from idle-cache correctness alone.

Report attempted/completed/cancelled/restarted/failed work, applicable success/effect correctness, useful throughput, end-to-end and p95/p99 latency, queue/resource peaks, persistence cost and reference/observer overhead at matched fixed load. Freeze numerical performance acceptance thresholds only after the complete workload and resource contract is specified, before execution; this note releases no experiment. H1 historical failures and closed observer/import prerequisites, and H3/H4 status, are unchanged.
