# Packaged graders need their own native inference accounting

Verifiers [draft PR 3158](https://github.com/PrimeIntellect-ai/verifiers/pull/3158), by `xeophon`, proposes routing packaged sandbox graders through the evaluator's existing host inference clients. It was open and unmerged when captured on 12 November 2026. The reviewed head is `8cdc3ea6bfccbb4e29dd2b59274ef36a2c1df3b4`; the observed target base is `d275fdf693f979794cdf7e49dc130c9f529c1493`. The exact GitHub comparison reports **merge base `ae5e56bc4e714c782817b4bde822fa084fc319d2`**, so its 15 changed-file patches describe that authored branch delta. They are not a direct diff from the current target tip.

The complete author body and all 15 changed-file patches were reviewed. Each patch's additions and deletions match the API counts, totaling 399 additions and 108 deletions. The scope covers changed production/caller hunks and documentation; complete unchanged implementations, dependency closure and tests were not fetched. For this source review, no upstream test, native runner, provider, model or scientific experiment ran.

The concrete caller is [Rollout.close](https://github.com/PrimeIntellect-ai/verifiers/blob/8cdc3ea6bfccbb4e29dd2b59274ef36a2c1df3b4/verifiers/v1/rollout.py), isolated [grade_task](https://github.com/PrimeIntellect-ai/verifiers/blob/8cdc3ea6bfccbb4e29dd2b59274ef36a2c1df3b4/verifiers/v1/grading.py), and `vf-validate` scoring. An optional `ScoringConfig.judge` wraps the packaged grader in `scoring_session`; `judge=None` keeps the existing runtime path. The session constructs a `JudgeSession` with the host `ModelContext` and client, binds a temporary endpoint/token into grader environment variables, and blanks mapped provider credential variables during verifier setup. A local interception pool is not reused when the verifier is remote. Harbor's verifier command preserves the bound proxy environment instead of overwriting it with credential templates.

The [interception server](https://github.com/PrimeIntellect-ai/verifiers/blob/8cdc3ea6bfccbb4e29dd2b59274ef36a2c1df3b4/verifiers/v1/interception/server.py) routes judge requests through the host client while recording judge responses and extra usage outside the solver's message graph and stop state. An unspecified judge model preserves the request's model; configured model/sampling overrides use the existing dialect path. Judge sessions share inference request/idempotence and handler-release machinery, but do not acquire rollout task-state or tool capabilities. Session release cancels tracked handlers and guards subsequent trace mutation. These are source observations about an in-memory lifecycle. They do not establish durable judge budgets, exactly-once provider effects, immutable scoring receipts across restarts or replay equivalence.

The author reports 238 passing unit tests with 18 runtime-dependent skips, nine live Prime checks, and three LAB RewardKit runs comprising 181 rubric calls. The body also describes temporary HTTP/concurrency/idempotence/credential/revocation smoke scripts. Those are **author-only, unreplicated claims**. None of the 15 changed paths is a test file; this review acquired neither permanent regression definitions for the new behavior nor independent CI evidence. The companion environment migration and live resources were not inspected or executed.

This supplies a specific H3/H4 integration point: a packaged judge's provider calls can have accounting and capability lifetime distinct from the solver that produced its submission. At higher fan-out, retries, simultaneous handlers and buffered/raw responses consume spend, memory and time beyond solver turn/token limits. A future justified study belongs in this actual scoring caller, retaining `judge=None` and the prior pinned runner as rollback. Before execution, separately fix solver episodes, judge requests/provider/version/seed, attempt and concurrency limits, token/time/artifact/memory ceilings, and scoring versions. Require immutable wire/store/score binding, exact retry/replay accounting, no admission after revocation, explicit failed/unscored denominators and defined recovery receipts across two process restarts. Any performance comparison must report applicable correctness/quality, useful throughput, end-to-end and p95 latency, appropriate peak memory/communication and observer cost against a matched baseline.

No such protocol is frozen or run here. This is a draft implementation proposal with bounded source evidence, not a dependency adoption or validated replacement for current evaluation gates. H1's negative cost/quality result and invalid historical parent RSS, H2's closed finite slices and failed concurrent freeze, and full H3/H4 unmet gates remain unchanged. The [curated receipt](receipts/20261112T022614Z-scoring-sessions.json) binds the exact capture, file/blob identifiers, patch hashes and limits; author measurements remain separate from our source observations.
