# Durable evaluation reservations in the actual runner: finite fixture result

One separately frozen v2 suite passed its finite engineering criteria on 2026-11-05. It used the genuine pinned `run_episodes -> Env.run_slot -> NullHarness subprocess -> EvalClient HTTP -> EchoTask` chain. Three native entries produced three single-trace `echoed` scores (0, 1, 1), with three received provider requests, no observed request retry, three worker PIDs and two verified SIGKILL/reopen transitions. A reserved development allowance was burned after its owner died; it was neither refunded nor replayed. The [earlier v1 attempt](../verifiers-budget-native-failed/report.md) remains failed, with all of its frozen inputs and 22 raw files unchanged.

The provider, answers and token usage are deterministic local fixtures. This result closes only this fixed reservation/recovery integration slice. Full H3 closed evaluation and H4 replay/scoring consistency remain unmet; there is no real-model quality, GPU, multi-node, production or general external exactly-once result.
