# H1 分配生命周期实验：预导入失败

本轮没有得到新的模型成本或显存结果。唯一冻结套件在第一个工作进程的
preimport 检查失败，停止后没有重跑；模型加载、前向、反向和优化更新均为零。
[原始结果与复核入口](../results/codec-allocation/report.md)保留失败。

错误来自我们调用已有验证器时混淆两个量：允许一次本地能力探测的**预算**，
和导入前尚未使用探测的**计数**。真实回执是预算 1、计数 0；父进程把计数 0
传给 `expected_budget`，而验证器已经根据阶段推导计数必须是 0。其余已保存
的阶段、身份、时间和线程条件符合要求。这不是观察到非法 provider 调用。
两个保留进程均强制退出，退出码 57347，Job 计数归零。

27 项运行前纯测试和独立静态审查未覆盖这处跨模块契约。冻结代码、协议和
原始结果不修改；事后增加的纯回归测试以真实回执驱动 mock Job 中的原始
`run_case` 分支，确认错误参数及放行前拒绝。独立 stdlib 复核还检查原本
未纳入顶层 `stages` 的失败原始回执。冻结审计 42 项一致性检查通过只说明
失败记录一致，执行接受仍为 false；不代表分配测量完成。

本次预注册的 raw 分配字节篡改、poststudy 旧 hash、跨臂梯度篡改三项控制
均未执行，因为相应产物不存在。事后失败回执审计的变异测试单列，不冒充
上述控制。下一次先单独冻结预算契约修正和使用真实验证器的 mock 握手测试，
再考虑新的实际套件。本轮不偷偷修复、不改阈值、不用另一测量接口补跑。

研究目标仍是解释残差 bank 的真实存储生命周期、打包/解包临时成本和训练
门槛。计划中的 CPU allocator request bytes 与弱引用存活状态，不能换算成
进程 RSS/private 释放、完整 native/GPU 峰值或模型质量。本次甚至未运行
profiler，因此接口可用性仍待核验。旧六项训练成本/终评负结果、无效历史
RSS、zero_grad 区间盲区保持；H2 实际恢复与 liveness、H3/H4 执行门槛不变。
