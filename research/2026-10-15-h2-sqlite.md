## 本项目的研究判断

H2 的下一步应检验：迁移或恢复工具是否把所有已接受工作的状态明确暴露出来，包括异常、阻塞和仍未完成的工作。报警、保留记录、原子提交、最终业务完成是不同性质。此次上游快速修订支持优先检查这些合同；不据此预测私有计划或宣称我们领先。

本轮只新增一个实验：[独立 SQLite migration probe](../experiments/sqlite_migration_probe.py)。使用标准库 SQLite、临时数据库和真实子进程硬退出，对比静默跳过与保留并报警。schema、fixture 和代码均为本项目独立实现；不是 OpenClaw 旧库升级复现。配置、逐次重开数据库的行快照、SQL dump、故障点及 hash 见[结果](../results/sqlite-migration/report.md)和[轨迹](../results/sqlite-migration/probe.json)。

实际执行 **2 策略 × 5 配置 = 10 条轨迹**；每条接受 6 项工作，含 3 条格式/版本异常行。5 个配置为无故障、事务内首条写入后、诊断步骤后、提交前、提交后。每条使用两个独立子进程，加上父进程重迁移检查；SQLite **3.53.1**、WAL、synchronous=FULL、BEGIN IMMEDIATE，无随机采样。

| 每条恢复后的指标 | 静默跳过 | 保留并报警 |
| --- | ---: | ---: |
| 原始 TEXT 行保留 | 6/6 | 6/6 |
| 无报警的坏行 | 3 | 0 |
| 误报干净 | 是 | 否 |
| 仍未分类 / runnable / blocked | 3 / 1 / 2 | 0 / 1 / 5 |
| 业务完成 / 未完成 | 0 / 6 | 0 / 6 |

10 条轨迹所测提交原子性与逻辑重放幂等检查均通过；3 个提交前硬退出点重开后均回滚至初态。**这也保留了负结果：显式报警没有让坏数据恢复或让任何业务完成。** 当前指标的异常真值来自固定 fixture 清单，不复用迁移 decoder。原行 hash 针对 SQLite TEXT 的 UTF-8 值，不是物理数据库文件字节。

一键复现完成 **50 项测试**、原有两项实验与本次实验；结果和代码 SHA256 见 [reproduction.json](../results/reproduction.json)。本实验结果 canonical SHA256 为 `4a1c4724212a1ae7a3c2f53e40a7707eb40e4623aeef3ae629f8f3c6cb51e639`。只有所测本地 fail-stop 边界得到验证；未覆盖并发写入、真实旧版本升级、电源故障或外部副作用。

先前 Recovery contract probe 的五项安全指标没有持久化的 accepted-turn/completed-result 账本。丢弃旧 turn 或崩溃丢失队列可能不计入任何一项违规。现已在其模型边界明确说明，零计数不支持 liveness 结论。
