# Evaluator entropy at the qualification boundary

On 7 November 2026, [feruap reported](https://github.com/SakanaAI/AI-Scientist-v3/issues/5) that an AI-Scientist-v3 repair responding to an anti-gaming finding inserted `secrets.token_bytes(32)` on every invocation of a simulation evaluator. The reporter describes about 0.2 spread in `combined_score` for an identical program, compared with improvements of about 0.15, and a run ending without a scored correct winner. A fixed task-owned secret reportedly restored equal scores in two evaluations. These are the reporter's observations. The original simulation scaffold and raw campaign outputs are absent; we have not reproduced the numbers, failure or repair.

Current public `main` was [df8313889a004f8a44a472e19a833cd547bb828a](https://github.com/SakanaAI/AI-Scientist-v3/blob/df8313889a004f8a44a472e19a833cd547bb828a/src/task_drafting/qualification.py), matching the reported version. The [qualification caller](https://github.com/SakanaAI/AI-Scientist-v3/blob/df8313889a004f8a44a472e19a833cd547bb828a/src/task_drafting/qualification.py#L363) invokes managed preparation once, checks publication-plan identity and creates a receipt with one finite baseline score. Its non-null install-cache directory disables the generic runtime's manifest-reuse shortcut, which can otherwise perform zero fresh evaluations. Following this caller through the complete [runtime source](https://github.com/SakanaAI/AI-Scientist-v3/blob/df8313889a004f8a44a472e19a833cd547bb828a/src/investigation/task_runtime.py#L2369), the captured successful contracted path calls `_run_contracted_baseline` once, runs the evaluator, validates its result and stores that one score. It does not compare separate identical evaluator invocations in this path. This is a source finding, not an executed failure or a repository-wide absence claim.

Existing controls matter. The baseline broker verifies the declared candidate reset transcript. The [final runner](https://github.com/SakanaAI/AI-Scientist-v3/blob/df8313889a004f8a44a472e19a833cd547bb828a/src/final_evaluation/runner.py#L1681) checks seed establishment and reset sequence, candidate/scaffold identity and sealed results. A valid reset transcript can coexist with additional private randomness inside an evaluator. Those controls therefore do not establish cross-invocation score equality. The draft prompt requests deterministic baseline behavior and the alignment prompt reviews reproducibility; neither statement is our evidence that the reported scaffold actually passed.

The mechanism differs from our [18 October protocol-drift review](2026-10-18-evaluator-protocol-drift.md), which concerned changing evaluation definitions or aggregation. Here fixed evaluator bytes can still yield different scores because their random inputs change. The narrow H4 implication is to distinguish evaluator identity, declared candidate seeds and observed score repeatability.

The concrete integration point is drafted-task qualification before investigation and publication, through the existing managed runtime and broker. The reporter already offers a PR pending agreement on where the second evaluation belongs; the captured issue has no maintainer response. We did not open a competing proposal. A future accepted native check would need fixed candidate/input/resource identities, predeclared metric fields and tolerance, valid deterministic and fresh-entropy controls, and failure before score selection. Comparing every byte of `metrics.json` or assuming every legitimate workload is bitwise deterministic is not an agreed contract. Two equal results alone would not prove determinism.

Any extra invocation must include startup, all episodes and RPCs, cleanup, resource use and observation cost within separately fixed ceilings. Repeating a sealed final evaluation would change a different contract. The existing final boundary permits bounded witnessed prestart launch retries; once-only scored final does not imply one physical launch attempt. A real integration should report success rate, useful throughput, end-to-end and tail latency and peak resources as applicable, alongside its score-integrity controls. None of those measurements or an experiment preregistration is supplied by this source review.

No upstream code was imported or tested, and no model, GPU, Docker or scientific suite ran. H1's negative training results and the existing H2-H4 statuses and finite closed gates are unchanged.
