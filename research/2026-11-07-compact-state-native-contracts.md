# Compact state buffers still need native replay and backend contracts

A fresh [collaborator review of FLA PR #1681](https://github.com/fla-org/flash-linear-attention/pull/1681#pullrequestreview-5810606177), submitted by `zhiyuan1i` at 06:44:52 UTC on 7 November 2026, requests changes to the proposed compact KDA state layout. We captured the complete review and PR and authenticated ten complete source/license files at the exact reviewed head, [`99f2e46b373bd1d96f5228d6dbbf84fb1e93faf2`](https://github.com/fla-org/flash-linear-attention/commit/99f2e46b373bd1d96f5228d6dbbf84fb1e93faf2). The PR is open and belongs to `mdy666`; we did not submit a competing repair. This is a source review, with no imported upstream code, tests, kernels or models run.

The actual caller is KDA forward/backward in packed variable-length training, including contiguous context parallelism (CP) and CUDA Graph replay. The proposal bounds checkpoint slots by token count instead of paying a rounded chunk per short document, and uses one cross-rank state slot. Its byte tables and H200 test results are the author's claims. Allocated logical buffers do not establish peak device memory, useful throughput or training quality.

The first review concern is a concrete selection mismatch. In the NVIDIA contiguous-CP singleton branch, `chunk_kda_bwd` sets `last_sequence_idx = len(cu_seqlens) - 2`. The common backward kernel gates the singleton `dht` load on `i_n == last_sequence_idx`. The existing graph test fills a static `cu_seqlens` buffer by repeating its final offset after the real sequences; its final metadata entry can therefore describe an empty padding sequence. CP forward preprocessing already selects the last nonempty sequence on device during graph replay. These source facts corroborate the boundary identified by the reviewer. The reviewer's claim that it drops the last real sequence's cross-rank gradient remains unreplicated: we did not execute `tests/cp/test_graph.py`, quantify a gradient discrepancy or establish which full configurations fail.

The second concern reaches the public dispatch chain. The compact fused caller passes `compact_h`, `compact_dh`, `dht` and `last_sequence_idx`. At the reviewed head, the TileLang verifier and implementation list none of those arguments and have no catch-all keyword parameter. `BaseBackend.verify` catches an exception and returns a rejection; the registry logs that rejection once at INFO level, tries any other eligible backend, then invokes the original implementation if none accepts. This corroborates a signature-to-selection failure path, conditional on that backend being available and enabled. It is not wholly silent, and we did not observe an actual route or speed regression. The review also alleges an intra-card CP verifier mismatch; we did not independently identify that specific adapter in the captured code. The captured NPU-only Ascend CP adapter is a different path and accepts catch-all arguments.

Our engineering inference is that checkpoint compaction has to preserve device-side sequence identity and the selected backend contract throughout the real training caller. A numerical comparison can pass while an intended backend is rejected, and a smaller buffer can coexist with an invalid replay gradient. Neither boundary supplies evidence for our H1 residual bank or repairs its saved negative training result.

If this optimization becomes relevant to a justified training integration, its native entry points and existing graph test are the integration points; no new observer prerequisite is needed. Before execution, a separate protocol must pin the patch and fallback, hardware/software, dtype and seeds, packed-length distributions, empty-tail replay cases, CP ranks, intended backend, load and resource ceilings. Acceptance must require the intended public-entry route, predeclared forward/full-gradient tolerances and rollback behavior, then matched held-out quality, useful end-to-end throughput, step/tail latency, peak device resources, communication and observation cost. Cold compilation and graph capture must be accounted for separately. These are proposed acceptance requirements, not a preregistered or executed study. All H1 negatives and closed or unmet H2–H4 gates remain unchanged.
