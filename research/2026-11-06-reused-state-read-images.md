# Reusing state-read images without losing source ownership

The landed [OpenClaw change 9f5e817](https://github.com/openclaw/openclaw/commit/9f5e817557791c720626bbe7e6e7671c22a93925), committed on 6 November at 12:02:59 UTC and attributed to `steipete`, replaces repeated private database copies in selected Doctor/update reads with reusable images. The previous radar already sampled the commit; this round adds pinned source and test-design review, not a new release or local benchmark. The author reports one 400 MB state database update writing 88 GiB, with 94% attributed to snapshots. Those figures remain unreplicated author claims.

The actual callers inspect state schema, owner leases and individual rows during Doctor/update preparation. Repeating a whole database copy for a small query can amplify physical work and extend an update outage. The integration adds `reuse: true` to selected read-only callers and wraps ordinary Doctor, Doctor-lint and delegated Doctor execution in an explicit reuse scope. Outside a scope, source capture cannot create a retained image; ordinary exclusive preparation remains available. This is an optional ownership optimization at existing callers.

The [new reuse implementation](https://github.com/openclaw/openclaw/blob/9f5e817557791c720626bbe7e6e7671c22a93925/src/infra/sqlite-snapshot-reuse.ts) keys its current-image map by canonical source path. It records main-file device, inode, size, mtime and ctime, plus the nonempty WAL's device, inode, size and mtime. A rollback journal disallows reuse. Empty WAL files and SHM files do not alter the fingerprint; WAL ctime is deliberately excluded because root SQLite can change it on open. Initial capture requires at least two seconds since the newest relevant mtime. This is a filesystem fingerprint contract, not a content hash or a proof for every filesystem mutation schedule.

Each successful borrow increments a lease count. A changed fingerprint or missing image retires the current entry, but existing readers retain their image until their last lease leaves. Scope exit retires remaining entries and awaits tracked retirement promises; retirement failures are logged and remain with existing cleanup/retry ownership. The cache therefore has one current entry per canonical source, with possible still-leased retired images. It does not impose a global image-byte, lease, database-count or disk-usage ceiling.

A producer binds its image to the fingerprint observed before copying. A late single-flight waiter cannot re-label that image with a newer source observation. The owned-connection path distinguishes logical backup images from exact artifact-preserving copies: only a logical reader may borrow a logical-only image. Expected physical identity and the existing native-source check prevent a retained owner of a replaced path from advertising its old bytes as that replacement. The owned backup dependency still rejects a closed connection or an active transaction. These are source-level guards; they do not establish arbitrary concurrent-writer, cancellation or crash correctness.

The new test definitions exercise file/WAL changes, aliases, replaced main files, rollback journals, recent timestamps, scope retirement, identity mismatch and producer-versus-waiter binding. They use ordinary file contents and fake retirement callbacks; the source work-count tests mock the snapshot worker with a file copy. We read these definitions and complete source versions but ran no local test, SQLite workload, model or scientific experiment. They provide test-design evidence, not measured physical-I/O savings, peak memory, two-process recovery or a production guarantee.

The [capture receipt](receipts/20261106T145232Z-openclaw-state-image-reuse.json) binds 46 complete immutable versions across 29 paths, including all 21 changed paths and their available parent versions. One guessed dependency filename returned 404; the caller's actual import was then captured under its correct name. The failure is retained separately. Only this narrative, metadata and hashes are published; captured upstream source remains ignored locally.

For our H2 engineering direction, this supplies a concrete read-amplification mechanism and an ownership boundary to preserve if a justified real caller later needs it. Any future comparison must separately fix database/WAL state, source replacements, active readers, query load, current authority, cancellation and two-reopen schedule. Preregister successful reads and ownership failures, useful throughput, full update/outage and tail times, physical bytes, peak resources, retirement completion and observation cost. This is a proposed boundary, not a registered or executed study, and creates no new observer prerequisite. Existing finite H2 and evaluation slices remain closed; H1 negatives and invalid historical RSS, and the full H3/H4 unmet gates, remain unchanged.
